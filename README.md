# 음주운전 체험 VR 게임

경찰 교통안전 홍보·교육용 음주운전 위험성 체험 게임입니다. 같은 코스를 일반 모드와
음주 모드로 각각 주행하고 반응 시간·정지 거리·위반 기록을 비교해 음주운전의 위험성을 체감하게 합니다.

휴대폰 + 카드보드형 VR 고글 + 블루투스 컨트롤러로 체험하는 것을 목표로 합니다. PC 크롬에서도
키보드로 테스트할 수 있습니다.

## 휴대폰에서 체험하기 (VR)

1. 휴대폰(안드로이드 크롬)에 블루투스 컨트롤러를 연결한다. 스위치 프로 컨트롤러나 일반 안드로이드 패드를 쓸 수 있다.
2. 배포 주소 **https://kkangpkm-eng.github.io/drunk-driveing-vr/** 에 접속한다.
3. 컨트롤러 버튼을 하나 눌러 "게임패드 연결됨" 문구가 뜨는지 확인한다.
   (브라우저는 버튼을 한 번 누른 뒤에야 패드를 인식한다.)
4. **VR 모드로 시작 (카드보드)** 를 터치하고, 휴대폰을 가로로 고글에 끼운다.
5. 이후 모든 조작은 컨트롤러로 한다. 정면이 틀어졌으면 **X(위쪽 버튼)** 를 눌러 정면을 다시 맞춘다.

VR 표시 방식:
- **WebXR**: 브라우저가 `immersive-vr`을 지원하면 사용한다. 머리 추적은 브라우저가 처리한다.
- **화면 분할 + 자이로**: WebXR 카드보드를 지원하지 않는 대부분의 안드로이드 크롬에서 자동으로 쓰인다.
  화면을 좌우로 나눠 양쪽 눈 화면을 그리고, 휴대폰 기울기 센서로 고개 방향을 따라간다.
  렌즈 왜곡 보정은 하지 않는다.
- 자이로와 VR은 **HTTPS에서만** 동작하므로, 휴대폰 확인은 GitHub Pages 배포본으로 한다.

## 실행 방법 (개발)

```bash
npm install
npm run dev     # http://localhost:5173
npm test        # 단위 테스트 (입력 지연 버퍼, 측정 모듈)
npm run build   # dist/ 에 배포용 빌드
```

개발용 URL 파라미터:
- `?mode=normal` / `?mode=drunk` — 첫 화면과 메뉴 없이 바로 해당 모드로 주행
- `?view=station` — 경찰서 전경
- `?view=intersection&cw=1` — `cw`번째 횡단보도 전경 (0~4)
- `?view=pedestrian&cw=1` — 강제로 적색 전환 + 보행자가 건너는 중인 장면
- 개발 서버에서는 `window.__game`(physics, signals, pedestrians, leadCar, metrics, vr 등)으로 상태를 조작할 수 있다.

## 게임 흐름

```
[첫 화면(HTML): VR 모드로 시작 / 화면 모드로 시작]
   → 시작 화면 → 모드 선택(일반/음주) → 주행 ⇄ 일시정지 → 결과 비교
                                             └→ 다른 모드 주행 / 다시 주행 / 모드 선택 / 처음으로
```

- 첫 화면만 HTML이다. 휴대폰에서 전체화면·VR·소리를 시작하려면 화면 터치가 한 번 필요하기 때문이다.
- 그 뒤의 시작 화면, 모드 선택, 일시정지, 결과 비교, 주행 중 알림은 모두 **장면 안의 3D 패널**이다.
  그래서 VR 화면에서도 보이고, 컨트롤러로 조작한다.
- 차량은 경찰서 주차장에서 정문을 바라보고 출발한다. 정문을 나가 우회전해 도로에 합류하고,
  코스 끝(1.8km)에 도착하면 결과 비교 화면이 열린다.
- 결과는 모드별로 마지막으로 완주한 주행이 저장된다. 두 모드를 모두 마치면 차이를 문장으로 알려준다.

## 조작법

| 동작 | 컨트롤러 (standard 배치) | 키보드 |
| --- | --- | --- |
| 조향 | 왼쪽 스틱 좌우 | ← → / A D |
| 가속 | ZR (또는 오른쪽 스틱 위) | ↑ / W |
| 브레이크 | ZL (또는 오른쪽 스틱 아래) | ↓ / S |
| 메뉴 이동 | 방향키 / 왼쪽 스틱 | 방향키 |
| 선택 | A 또는 B (아래·오른쪽 버튼 모두) | Enter / Space |
| 뒤로 | − (Select) | Esc / Backspace |
| 일시정지 | + (Start) | P / Esc |
| VR 정면 재설정 | X (위쪽 버튼) | C |
| VR 켜기/끄기 | — | V |
| 개발용: 재시작 / 다른 모드로 재시작 / 결과 화면 / 입력 디버그 | — | R / M / T / I |

- 스위치 컨트롤러의 ZL/ZR은 디지털 버튼이다. 그래서 누르면 키보드처럼 서서히 100%까지 올라간다(`gamepad.digitalRampUpPerSec`).
  세밀하게 조절하려면 오른쪽 스틱 상하를 쓴다.
- 아날로그 트리거가 있는 패드는 누른 만큼 그대로 반영된다(자동 감지).

## 구현 내용

### 1~2단계: 기본 주행 + 음주 모드
- 완만한 커브 3개가 있는 편도 2차로 코스, 로우폴리 배경(인스턴싱), 1인칭 운전석(실제로 돌아가는 핸들, 속도계)
- 아케이드식 차량 물리, 도로 이탈 시 감속·진동
- **음주 모드**: 입력 지연 버퍼(`inputDelayBuffer.js`), 조향 감도 저하·노이즈·과조향·반응 둔화,
  브레이크 약화(`drunkControl.js`), 바깥 풍경 흔들림(차량 그룹 전체를 굴려 실내는 고정), 이중 시야, 블러, 터널 시야
- 핸들은 지연·왜곡을 거쳐 실제로 차에 반영된 값을 따라 돈다.

### 경찰서 출발 (`src/scene/policeStation.js`)
- 본관(흰 벽)·별관(회색 벽), 파란 띠, CanvasTexture 창문과 간판(문구는 config), 담장·정문(기둥 표지판),
  태극기 게양대, 순찰차 2대(InstancedMesh), 주차 구획선(InstancedMesh)
- 주차장 부지 안은 도로 이탈로 판정하지 않는다.

### 신호등 횡단보도 5곳 (`src/scene/intersection.js`, `src/traffic/trafficSignal.js`)
- 코스의 직선 구간에 5곳을 둔다(`config.crosswalks`). 교차 도로가 있는 교차로 3곳(z=600, 860, 1500)과
  단독 횡단보도 2곳(z=160, 1330)이다.
- 줄무늬(도로면보다 1cm 위)·정지선·신호등 기둥은 5곳 전체를 InstancedMesh로 그린다.
  교차 도로·보도 블록은 하나로 병합한다.
- 신호등은 기둥 + 도로 위 암 + 가로형 3구 등(적·황·녹)이고, 기둥 중간에 보조 신호등이 하나 더 있다.
  점등은 emissive 밝기로만 표현하고, PointLight는 옵션이다(기본 끔).
- 차 앞범퍼가 정지선에서 `triggerDistanceM` 안으로 들어오면 녹 → 황 → 적으로 바뀐다.
  횡단보도마다 `greenHoldS`가 달라서 언제 바뀔지 예측하기 어렵다.
- 적색일 때 앞범퍼가 정지선을 넘으면 **신호위반**으로 기록한다.

### 보행자 (`src/traffic/pedestrians.js`)
- 횡단보도마다 2명이 있다. 적색이 켜지면 각자 `delayAfterRedS`초 뒤에 초속 1.3m로 건너고, 일반/음주 모드에서 똑같이 나온다.
- 차가 거의 멈춘 채 앞을 막고 있으면 보행자가 기다린다. 움직이는 차에 닿으면 **보행자 충돌**로 기록한다.
  이때 보행자를 장면에서 빼고, 붉은 화면 점멸과 경고음만으로 알린다. 사실적인 묘사는 없다.
- 운전자와 260m 이상 떨어진 보행자는 숨기고 애니메이션도 갱신하지 않는다(모바일 성능).

### 앞차 급정거 (`src/traffic/leadCar.js`)
- 운전자가 z=900을 지나면 같은 차로 110m 앞에 앞차가 나타난다. 처음엔 느리게 달려 운전자가 따라붙게 하고,
  그 뒤에는 차간 거리 약 22m를 유지한다.
- z=1120(곡선 구간)에서 브레이크등을 켜고 8m/s²로 급정거한다. 3초 정지한 뒤 다시 출발해 멀어지면 사라진다.
- 앞차도 신호를 지킨다(전방 신호가 녹색이 아니면 정지선 앞에서 선다).
- 추돌하면 **앞차 추돌**로 기록하고 점멸 + 경고음으로 알린다. 차는 앞차를 뚫고 지나가지 않는다.

### 측정 모듈 (`src/measurement/runMetrics.js`)
| 항목 | 정의 |
| --- | --- |
| 반응 시간 | 위험 신호(앞차 브레이크등, 신호 황색 전환)가 시작된 순간부터 **원래** 브레이크 입력(지연·왜곡 전 = 운전자의 실제 반응)이 0.2를 넘을 때까지 |
| 반응 실패 | 5초 안에 브레이크를 밟지 않은 경우. 단, 신호에서 브레이크 없이 정지선을 그냥 지나가면 반응 표본에서 빠진다(신호위반은 따로 기록) |
| 앞차 급정거 정지 거리 | 앞차 급정거 시작부터 내 차가 멈출 때까지 이동한 거리 (공주거리 + 제동거리). 그 사이 추돌하면 "추돌" |
| 신호위반 / 보행자 충돌 / 앞차 추돌 | 횟수 |
| 도로 이탈 | 벗어난 횟수와 도로 밖에 있었던 총 시간 |
| 완주 시간 / 평균 속도 | 출발부터 코스 끝까지 |

### VR (`src/vr/vrManager.js`, `src/effects/vrVignette.js`)
- 카메라는 운전석 눈 위치의 "카메라 리그" 안에 있어서, VR 머리 회전은 카메라의 로컬 회전으로만 적용된다.
  그래서 차가 움직이고 흔들려도 머리 추적과 섞이지 않는다.
- VR 중 음주 효과는 아래처럼 동작한다.
  - 흔들림: 그대로 적용한다.
  - 터널 시야: 카메라에 붙인 3D 판으로 그려서 양쪽 눈에 모두 맞게 보인다.
  - 블러: 화면 분할 방식에서만 쓴다(`vr.blurInStereo`).
  - 이중 시야: 꺼진다. 포스트프로세싱은 VR에서 쓸 수 없다.
- VR 중에는 화면 꺼짐 방지(Wake Lock)를 요청하고, 해상도 배율을 `vr.pixelRatio`(기본 1.0)로 낮춘다.

### 성능
- 반복 오브젝트(가로수·가로등·건물·횡단보도 줄무늬·정지선·신호등·주차선·순찰차)는 InstancedMesh로 그린다.
  정적인 부품은 버텍스 컬러로 칠해서 병합한다.
- PC 측정값(일반 모드 주행): 드로우콜 약 43~53회, 삼각형 약 1.6만 개. 화면 분할 VR은 이것을 양쪽 눈에 한 번씩 그린다.
- 실제 휴대폰의 60fps 여부는 실기기에서 확인해야 한다. 버벅이면 아래 순서로 낮춘다.
  `vr.pixelRatio` 0.8 → `drunk.visual.lowSpecMode = true` → `render.fogFarM` 축소 → `pedestrians.activeDistanceM` 축소.

## 조정 가능한 수치 (`src/config.js`)

| 값 | 설명 |
| --- | --- |
| `vehicle.*` | 가속/제동/조향 물리, 정지선·충돌 판정용 차체 크기 |
| `course.*` | 출발 위치·방향 (경찰서 주차장) |
| `road.*` | 코스 시작 z, 길이, 폭, 이탈 페널티 |
| `policeStation.*` | 간판 문구, 부지·담장·정문, 본관·별관, 게양대, 순찰차, 색상 |
| `crosswalks[]` | 횡단보도 위치(z), 교차로 여부, 항목별 신호·보행자 설정 덮어쓰기 |
| `crosswalkDefaults.*` | 교차 도로 크기, 줄무늬·정지선, 신호 시간(`triggerDistanceM`, `greenHoldS`, `yellowDurationS`, `redDurationS`), 점등 밝기 |
| `pedestrians.*` | 보행 속도(1.3m/s), 키, 모델, 출발 방향·지연, 표시 거리 |
| `leadCar.*` | 앞차 등장 위치, 차간 거리, 급정거 위치·감속도, 정지 시간, 색 |
| `measurement.*` | 반응 판정 임계값, 반응 제한 시간, 정지 판정 속도 |
| `collisionFeedback.*` | 점멸 색·강도·횟수, 경고음 주파수·음량, 충돌 시 차량 정지 여부 |
| `gamepad.*` | 축/버튼 번호, 데드존, 조향 곡선, 디지털 버튼 보간 속도, 메뉴 버튼 |
| `vr.*` | WebXR 우선 여부, 양안 간격, 화면 분할 시야각, 해상도 배율, VR 터널 시야 각도, 블러 허용 |
| `ui.*` | 3D 메뉴/알림 패널 거리·크기·표시 시간 |
| `drunk.*` | 음주 효과 강도, 입력 지연, 조향/브레이크 부정확성, 시각 효과 |
| `debugViews.*` | 개발용 고정 시점 |

도로 커브 형태는 `src/scene/road.js`의 `CURVE_SEGMENTS`에서 조정한다. 횡단보도는 직선 구간
(0~250, 500~950, 1250~1550m)에만 둘 수 있고, 벗어나면 콘솔에 경고가 나온다.

## 테스트

- 단위 테스트(`npm test`, `tests/`): 입력 지연 버퍼 보간, 반응 시간·반응 실패·정지 거리·도로 이탈 계산.
- 화면 흐름은 Playwright로 PC 크롬에서 가짜 블루투스 패드를 연결해 확인했다.
  확인한 흐름: 첫 화면 → 시작 → 모드 선택 → 주행(패드 가속·조향) → 신호 반응·정지 → 앞차 급정거 반응·정지 거리
  → 일시정지/계속 → 완주 → 결과 → 음주 모드 주행 → 결과 비교 → 화면 분할 VR.

## 실기기에서 확인해주세요

1. 휴대폰 크롬에서 배포 주소를 열고, 컨트롤러 버튼을 누르면 "게임패드 연결됨"이 뜨는지
2. VR 모드로 시작했을 때 화면이 좌우로 나뉘고, 고개를 돌리면 시점이 따라오는지 (방향이 반대거나 기울면 알려주세요)
3. 고글을 쓴 상태에서 메뉴 글씨가 읽히는지 (작으면 `ui.menuDistanceM`을 줄이거나 `ui.menuWidthM`를 키움)
4. 왼쪽 스틱 조향, ZR 가속, ZL 브레이크, A 선택, + 일시정지, X 정면 재설정이 기대대로 동작하는지
   (버튼이 다르게 잡히면 `gamepad.*` 버튼 번호를 바꾸면 된다)
5. 음주 모드의 흔들림·블러·터널 시야가 VR에서 너무 어지럽지 않은지
6. 주행이 끊기지 않는지 (끊기면 위 "성능" 항목 순서대로 낮춤)
